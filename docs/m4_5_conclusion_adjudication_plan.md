# M4.5 — Conclusion Adjudication Plan

## Why this is the next milestone

M4.4 proved that Codexia can freeze one comparison policy before run evidence exists, execute and verify the complete declared evidence set, and recover the same `SUPPORTED` / `REFUTED` / `INCONCLUSIVE` comparison result after restart.

That result is still not a scientific conclusion by itself.

The next failure mode is semantic inflation:

```text
policy-local comparison outcome != unrestricted scientific conclusion
```

A model or human must not be able to take a valid M4.4 result and silently strengthen it into a broader statement such as “the hypothesis is universally true/false”, replace the verdict, or attach evidence from a different comparison while preserving the appearance of governed adjudication.

M4.5 therefore starts from a second authority separation:

```text
human/model wording != conclusion adjudication authority
```

## Relationship to the M4.1 `Conclusion`

M4.1 deliberately defined a single-experiment `Conclusion` contract. It binds one exact `ExperimentManifest` and permits only metric/artifact evidence from that manifest.

That boundary remains valid and is not rewritten retroactively.

An M4.4 comparison is fundamentally cross-experiment: it binds one baseline manifest and one candidate manifest under one exact hypothesis. Converting an M4.4 result directly into the old single-manifest `Conclusion` would either discard one arm or falsely pretend that cross-arm evidence belongs to one manifest.

M4.5 therefore introduces a distinct stronger comparison-adjudication record rather than widening the M4.1 contract in place.

## Milestone question

> Given one exact recovered frozen comparison policy and its exact recovered M4.4 result, can Codexia produce one deterministic, policy-scoped, evidence-bounded conclusion whose verdict and wording cannot be selected or strengthened by the caller, then recover the same conclusion after restart?

The guarantee is deliberately narrow. M4.5 can prove the relationship between a declared hypothesis, frozen comparison criterion, verified evidence set, comparison result, and policy-scoped conclusion. It does not prove scientific truth outside that scope.

## Semantic boundary

The first M4.5 conclusion scope is exactly:

```text
frozen_comparison_policy.v1
```

The adjudicated verdict maps deterministically:

```text
ComparisonOutcome.SUPPORTED    -> ConclusionVerdict.SUPPORTED
ComparisonOutcome.REFUTED      -> ConclusionVerdict.REFUTED
ComparisonOutcome.INCONCLUSIVE -> ConclusionVerdict.INCONCLUSIVE
```

This mapping means only:

- `SUPPORTED`: the verified evidence satisfied the exact frozen comparison criterion;
- `REFUTED`: the verified evidence did not satisfy the exact frozen comparison criterion;
- `INCONCLUSIVE`: the frozen policy produced no supported/refuted result because its precommitted evidence rule admitted an inconclusive comparison.

It does **not** mean that the hypothesis is universally true or false, that the experiment is unbiased, or that alternative scientific interpretations are impossible.

## Caller authority rule

The normal adjudication API must not accept:

- caller-provided verdict;
- caller-provided conclusion summary;
- caller-provided conclusion id;
- caller-selected metric/artifact subset;
- caller-selected replacement policy/result digest;
- a different baseline or candidate manifest.

The conclusion identity, verdict, bounded summary, scope, and evidence lineage are derived from exact recovered M4.4 state.

## Three delivery slices

### M4.5.1 — Deterministic policy-scoped conclusion contract

Goal: establish the semantic authority boundary before adding persistence.

Deliverables:

- immutable digest-bound `AdjudicatedConclusion`;
- explicit fixed conclusion scope `frozen_comparison_policy.v1`;
- exact hypothesis id/digest binding;
- exact baseline and candidate experiment id/manifest digest binding;
- exact policy id/digest/freeze digest binding;
- exact comparison result id/digest binding;
- deterministic verdict mapping from `ComparisonOutcome`;
- deterministic bounded summary generated by the runtime rather than supplied by the caller;
- deterministic conclusion identity from the exact comparison result;
- strict decoder and tamper/rebinding regressions;
- no persistence, execution, model/provider, filesystem, Git, or scheduling authority.

Exit gate:

> For one exact recovered M4.4 policy/result pair there is one canonical policy-scoped conclusion identity, verdict, summary, and digest; the caller cannot substitute another verdict, wording, arm, policy, or result through the normal adjudication path.

### M4.5.2 — Durable conclusion registry and restart recovery

Goal: persist adjudication without turning the persisted row into semantic authority.

Deliverables:

- one deterministic durable adjudication per exact comparison result;
- SQLite persistence in the existing M4 trust domain;
- exact policy/result dependency indexes;
- recovery that re-recovers M4.4 policy/result and recomputes the expected conclusion;
- canonical payload/index/digest tamper detection;
- idempotent publication after interruption;
- no “latest conclusion wins”, automatic supersession, or conflict-resolution semantics.

Exit gate:

> A persisted conclusion is valid only when fresh recovery of its exact M4.4 dependencies deterministically reproduces the same adjudication; database text alone cannot mint or alter a conclusion.

### M4.5.3 — First real conclusion closure

Goal: use the existing M4.4.3 refuted experiment end to end rather than create another abstraction layer.

Deliverables:

- adjudicate the already-frozen M4.4.3 comparison whose exact policy result is `REFUTED`;
- preserve the policy-scoped wording rather than upgrading it into unrestricted scientific falsity;
- durable publication and fresh-process recovery from only the SQLite path plus stable conclusion/policy identity;
- prove no experiment rerun, no comparison reevaluation with a replacement criterion, and no caller-provided conclusion text;
- source audit and milestone closure document;
- roadmap transition to the next milestone only if the exact candidate passes cross-platform CI and CodeQL.

Exit gate:

> Starting only from durable state after restart, Codexia reconstructs the same evidence-bounded policy-scoped conclusion from the exact frozen policy and verified comparison result without rerunning experiments, changing the criterion, or accepting caller-authored adjudication semantics.

## Explicit non-goals

Do not add these merely because they are nearby:

- scientific truth scores;
- confidence intervals, p-values, Bayesian evidence, or new statistics;
- model-authored conclusion summaries presented as governed adjudication;
- automatic literature review or external evidence synthesis;
- automatic conflict resolution between multiple studies;
- “latest conclusion wins” semantics;
- automatic recommendation or action authority based on a conclusion;
- autonomous experiment scheduling;
- remote execution;
- TUI or plotting.

## Anti-drift criterion

A proposed M4.5 change should answer at least one of these:

1. Does it prevent caller/model wording from becoming adjudication authority?
2. Does it bind the conclusion exactly to the frozen policy and verified comparison result?
3. Does it make conclusion publication/recovery deterministic and tamper-evident?
4. Does it directly falsify an assumption required by one of the above?

If the answer to all four is no, the change is outside the M4.5 critical path.
